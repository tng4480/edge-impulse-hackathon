# Stress lab results (simulated stressors on recorded ICU data)

Every row applies a **simulated stressor** to the recorded vitals of all held-out test patients (476 sepsis, 7422 non-sepsis; md5 split as in `training/strict_eval.py`) and re-scores them hour by hour. Model: LightGBM trees at the device cutoff 0.55. NEWS2 rule: 4-vital score 5+ or any single 3, values carried forward. Flagged = an alert in hours onset−24 to onset−1 (onset = first SepsisLabel hour + 6). False alerts = separate alert episodes per patient-day in non-sepsis patients. Generated by `training/stress_eval.py`; raw numbers in `training/out/stress_eval.json`.

These are illustrations of failure modes, not corrections. The SpO2 over-read rows illustrate the bias reported by Sjoding et al., NEJM 2020 (doi 10.1056/NEJMc2029240) with a fixed offset; real over-reading varies by device and patient.

## Reading it honestly

- **Missing core temperature hurts the model most.** It is the live wearable situation (the watch reads wrist skin, not core), and the model's catch rate falls far more than the NEWS2 rule's. Its fewer false alerts come from the same lost signal, so they are not a gain. On the device the model gets an estimated core temperature (wrist skin plus a fixed offset), so real performance probably sits between the baseline and this row, but that is not measured here.
- **A beta-blocker hurts the model more than NEWS2.** The model leans on heart-rate trends, and capping HR at 80 bpm removes them.
- **SpO2 over-reading hurts NEWS2.** Its SpO2 item scores fewer points, so it catches fewer sepsis cases (the safety risk Sjoding et al. describe). The model's catch rate does not fall and its alarm time rises. This is **not** robustness: the model seems to treat SpO2 near 100 % as a risk marker, probably an ICU artefact (patients on supplemental oxygen). Neither method corrects the bias; the fixed offset is an illustration.
- **Missing or sparse SpO2** costs both methods a similar amount.
- **A 2-hour walk** adds false alerts for both. NEWS2 adds more separate alerts per day and both add about the same alarm time. The device's motion context should suppress or label these.
